What a partner invite looks like when it arrives, three treatments (issue #172)
Today the link previews as the marketing card: a watercolour house and "Juniper: build your financial future, together". Nothing in it says somebody invited you, and the house is about buying a home rather than about the person who sent it. Each treatment below is shown where it is actually read, in the message, then as the card at size, then as the page the link opens.
One constraint decides how far any of this can go, so it is stated before the treatments. A link preview is built by a crawler (Apple's, WhatsApp's, Slack's) that fetches the URL and reads the HTML. It does not run JavaScript. Juniper is a Vite SPA behind one static index.html, and every route including /invite/partner/:token is served that same file with the marketing tags in it, so no amount of React can change what the recipient sees in the bubble. Anything invite-specific in a preview needs the invite route to be served its own HTML: a second static entry for a fixed card (A), or an edge function for a card that knows who sent it (B and C).
And a second thing, which is a decision rather than a constraint. Naming the inviter in a preview puts their first name in front of whoever holds the link, which includes the crawler and, in a group chat, everybody in it. That is the point of an invitation, and it is still worth choosing on purpose rather than arriving at.
A An invitation, not a house
One card, the same for every invite. The illustration goes entirely: pine ground, the mark, and a sentence that cannot be read as anything but an invitation. It never names anybody, so it needs no lookup, no edge function and no per-request work: a second HTML entry point (invite.html) with its own tags, and a rewrite from /invite/partner/* to it. The trade is that "someone" is doing the work a name would do.

B The name does the work
Same card, and the headline says who. "Finley invited you to Juniper" is the bold line in the bubble, which is the first thing read and the only one that answers "why am I being sent this". The image stays static, so nothing is generated per request; the invite route is served by an edge function that resolves the token to the inviter's first name and returns the built index.html with three tags swapped. A token that is spent or unknown falls back to A's wording rather than to a blank.

C The name in the picture
The card is drawn per invite, and the name is in the art. The illustration is the one the marketing site already uses, cropped off the house and onto the two people, so nothing new has to be drawn or licensed, with a band carrying the invitation. Rendered by @vercel/og from the same markup this preview is built from, cached per token. It is the most obviously personal of the three and the only one where the picture itself says what happened.
